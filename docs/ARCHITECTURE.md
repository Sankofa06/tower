# Tower architecture

Tower has one reusable skill and one job: preserve visibility as work becomes multi-stage or multi-agent.

## Boundaries

Tower sits above individual task execution. Repository guidance, specialist skills, and explicit user authority remain controlling. Tower never grants permission to commit, push, deploy, release, change an account, or make another external mutation.

## Control surfaces

1. Commission — outcome, non-goals, phase, authority, and next decision.
2. Talent routing — match cost and reasoning to the expected decision value.
3. Persona contracts — assign exclusive deliverables, not merely stylistic identities.
4. Gates — transition only when the prior phase has an inspectable result.
5. Control view — make ownership, next decisions, blockers, and artifacts easy to scan.

## Relationship to The Perfect Agent

The Perfect Agent provides durable governance, memory, role boundaries, and proportionate independent assurance. Tower is the initiative-level control layer that decides how to spend attention and model capacity before and during a program. Either can be useful alone; together, Tower supplies the operating picture while The Perfect Agent supplies the durable accountability framework.
